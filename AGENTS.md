# Agent Instructions

## Repository Purpose

This repository owns Baixada's authoritative two-player Truco rules engine and
its direct language bindings. It implements, but does not redefine, the
versioned contracts published by
[`baixada-cards/truco-spec`](https://github.com/baixada-cards/truco-spec).

## Canonical Boundaries

- `crates/truco-engine` is the authoritative Rust implementation.
- `crates/truco-engine-py` and `python/truco_engine` are a thin Python binding.
- `typescript` is an independent conformance implementation used for parity
  checks; product-specific state and UI do not belong here.
- `spec.lock.json` pins the exact `truco-spec` revision used by conformance
  tests. Never point it at a moving branch.
- `.cache/truco-spec` is generated by `scripts/sync_spec.py` and must not be
  committed.
- HTTP sessions, bots, solver code, deployment, and complete applications live
  in their own repositories.

## Workflow

- Run `make check` before wrapping up a change.
- Use `sfw` for public-registry dependency fetches and preserve the seven-day
  dependency-age policies.
- Keep lockfiles current and use frozen/locked installs in CI.
- Sign commits.
- Changes in game behavior begin in `truco-spec`; update the pinned revision
  here only after the new contract is released and this repository conforms.
- Do not copy fixtures into this repository. Tests consume the pinned contract
  checkout prepared by `make sync-spec`.

## Verification

- Rust changes: `cargo fmt --check`, Clippy with warnings denied, and all
  workspace tests.
- Python binding changes: `uv run --no-sync pytest tests/python`.
- TypeScript changes: `pnpm --dir typescript typecheck` and
  `pnpm --dir typescript test`.
- Contract changes: `python3 scripts/sync_spec.py --check`, followed by every
  language's fixture suite.
